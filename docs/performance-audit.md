# 遊戲卡頓與旋轉畫面檢查

2026-10-18，台北時間。範圍為中央站 9 款遊戲；對照基準為 `3633c0f`。

目前找到的主要負擔在瀏覽器內：重複更新網頁介面、過多 3D 繪圖呼叫、爆炸漸層反覆建立，以及守城遊戲未回收的 GPU 資源。這些問題已修正。旋轉方面，也重現了暫停畫布比例錯誤及準星跑到螢幕外。

## 量測條件

- macOS 上獨立的無頭 Chrome；手機視窗 844 × 390、裝置像素比 3、觸控模式。
- 一般效能取樣：進場後暖機 1.5 秒，CPU 模擬降速 4 倍，取樣約 3.5 秒。
- 爆炸、場景繪圖與資源回收另用固定亂數對照；場景繪圖呼叫不等同 FPS。
- 旋轉矩陣：9 款 × 5 種尺寸，共 45 組。尺寸為 390 × 844、844 × 390、768 × 1024、1024 × 768、1366 × 768。
- 桌機 GPU 仍足以讓大部分取樣維持約 60 FPS。下列數字證明工作量降低，不能換算為學生手機會快幾倍，也不能取代 iPhone／iPad Safari 實機測試。

守城另將倒數與狀態文字改成有變才寫，最後一次取樣的版面重算由 223 次降至 4 次。一般取樣包含隨機場景變化，數字適合確認反覆工作是否消除，不作嚴格跨裝置排名。

觸控裝置的全螢幕畫布採最高 1.5 倍像素比，桌機最高 2 倍；原本 2 倍的觸控畫布像素量減少約 44%。坦克與守城在觸控裝置停用額外的 WebGL 抗鋸齒。遊戲內畫面可能稍軟，HTML 按鈕與題目不受此解析度上限影響。挖金礦仍保留既有 1080 × 675 遊戲座標，攻防戰橫式仍保留 900 × 360。

## 旋轉問題

1. 攻防戰暫停後轉直式：CSS 已變直式，繪圖仍用 900 × 360；原版實測畫布顯示為 372 × 482，造成拉伸。修正後暫停中也會依新容器尺寸重畫，時間與戰鬥不前進。
2. 海岸防線轉直式：原版準星 x = 832，但新畫面寬只有 390，準星消失。現在同步換算瞄準、火箭與特效的畫面座標，並清除舊拖曳狀態。
3. 坦克、狙擊與挖金礦：旋轉後清除舊觸控狀態；發音透明按鈕重新對齊，狙擊鏡頭隨 HUD 新尺寸調整。
4. 炸彈英文原本一次旋轉可能連續多次清空、重建畫布。現在合併同一幀的尺寸事件，只在實際尺寸變更時重建，並保留 iOS 尺寸穩定後的補測。
5. 海岸防線的彈藥顯示原本與統一移到右上角的暫停鈕重疊；已留出按鈕及安全區空間，橫式題目也避開此區。

共用 `game-runtime.js` 接收視窗、visualViewport、容器尺寸及字型載入變化。使用一般隱藏 canvas 作快取，沒有引入需要額外相容性處理的 OffscreenCanvas worker。

## 網路與檔案大小

單款 HTML／主要遊戲 JS 約 48–138 KB，另有共用程式；炸彈 HTML 很小，主程式另存於 JS。整個 assets 目錄約 45 MB，不會在開一款遊戲時全部下載。較大的檔案是每款約 4–7 MB 的背景音樂，以及挖金礦約 2.2 MB 的背景圖。

坦克與守城仍從 CDN 載入 Three.js；部分字型也有外部來源。這些會影響第一次開啟或首次播放，弱網路時仍可能等待。移動、碰撞與爆炸沒有逐幀伺服器往返，因此本輪先處理已重現的繪圖與版面負擔，沒有把 Service Worker 快取當成掉幀修法。

## 驗證與重跑

所有變更的內嵌 script 與 JS 都經 `node --check`；已檢查完整 diff，沒有更動題庫注入與語音解鎖流程。45 組尺寸切換未出現 JavaScript 例外、零尺寸畫布或頁面水平溢出；彈藥／暫停按鈕也沒有重疊。另以桌機鍵鼠模式驗證 9 款遊戲：載入後切斷測試瀏覽器網路，遊戲時間與邏輯仍持續前進，沒有 JavaScript 例外。這不代表整個網站已支援離線重新載入；詳細數字見相鄰的 JSON 紀錄。

保留三個需明確要求才執行的瀏覽器檢查，不加入自動啟動流程：

```sh
python3 -m http.server 8765 --bind 127.0.0.1
# 另開終端；需要環境中已有 Playwright 與 Chromium。
node tests/mobile-regressions.cjs
node tests/desktop-offline.cjs
node tests/performance-sample.cjs sample
# 如需只測指定遊戲：
node tests/performance-sample.cjs sample sniper,gun
# 如需重現舊版對照：
BASELINE_REF=3633c0f node tests/mobile-regressions.cjs
```

可用 `PLAYWRIGHT_MODULE` 指定既有 Playwright 套件路徑，`CHROME_PATH` 指定 Chrome 執行檔。預設連線本機 8765，輸出至系統暫存目錄，不替專案安裝 npm 套件。`GAME_URL`、`AUDIT_DIR`（效能取樣）及 `AUDIT_OUTPUT`（回歸 JSON）可另行指定。

實機複驗優先：手機／平板連玩守城 5–10 分鐘，連續產生爆炸；遊戲中及暫停時各做橫 → 直 → 橫；繼續後檢查瞄準、移動與單字發音。Safari 的實際 GPU、溫控降速與發音音訊行為，仍需在使用者裝置確認。

快取背景與重用圖像的依據見 [MDN Canvas 效能指南](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas)；GPU 資源需明確釋放的依據見 [Three.js 資源清理說明](https://threejs.org/manual/pages/cleanup.html)。


## 追加：跑酷、炸彈英文與屋頂題目／坦克命中

2026-10-18，依使用者補充進一步檢查；本段對照基準為上一輪修正版 `0f406c7`。數據存於 `focused-gameplay-audit.json`。

- **炸彈英文確實有換題定格。** 答對後的 54 次更新（約 0.9 秒）提前返回，連爆炸、房屋倒塌、加分文字也停止。以真正的炸彈／房屋碰撞重現：答對後再執行 30 次更新，舊版爆炸半徑一直是 9，房屋下沉量一直是 0；新版分別前進至 279、75，加分文字也繼續上浮。仍保留換題期間的飛機／敵人安全暫停，不會多扣血或提前換題。
- **炸彈的重複繪圖。** HUD 與題目改成小型透明圖層，分數、時間、彈藥、題目、尺寸、字型改變才重畫；低彈藥閃爍框仍即時更新。同一狀態連續繪製 120 次，文字繪製由 1,560 次降為 13 次，改分數後會再畫 13 次。此數字代表工作量；同步微測試會包含離屏圖層首次配置，且繪圖可延後執行，不能拿其耗時換算手機 FPS。
- **高更新率平板。** 以 120 個 120 Hz 時間戳驅動真正主迴圈，場景繪製由 120 次減為 59 次，邏輯更新前後都是 59 次（邊界的浮點餘數保留在累加器）。一般約 60 Hz 的 60 個時間戳仍畫滿 60 次，避免為了省繪圖反而產生跳幀。旋轉會強制重畫。
- **跑酷。** 題目板改以 transform 出入場，消除無意義的角色 class 反覆寫入；手機滑動答題約 5.2 秒，角色 class 變動由 317 次降為 0 次，兩版均答對 1 題、保留 3 顆愛心。平板也略過不可見的方塊背面與底面，角色面數由 36 降為 24，停用移動字牌的裝飾陰影動畫。橫直切換會取消舊手勢並暫停，讓學生準備好再繼續。
- **跑酷的思考減速仍保留。** 靠近題目時，跑道會刻意降至 20% 速度，前期約 1.5 秒，之後逐步縮短；這是既有答題機制，不代表網路延遲。這次沒有取消思考時間、改跑速或改碰撞規則。真機仍卡時，需區分這段平順減速與不規則掉幀。
- **殭屍守城屋頂題目。** 依使用者確認，只調整屋頂圖／字牌。圖片改方形、去除兩側空白；觸控最低牌高由 64 改為 88 CSS px，單字牌由 42 改為 52 CSS px，仍受長字寬度上限約束。保留依距離保字級，並為窄手機的 8 圖片關卡新增左右避讓；屋頂連線只接到牌子邊緣，不穿過圖／字。操作按鈕未改。
- **坦克樹上標的。** 字牌命中半徑由 3.2 改為 3.8，樹幹由 2.6 改為 3.0；桌機瞄準輔助使用同一字牌半徑。改成檢查上一幀到這一幀的整段路徑，先算最近標的。以實際約 4.4 世界單位／幀的砲彈重現擦邊漏算，修正後可命中；射偏、射過樹頂不算，錯誤選項仍算答錯，同一路徑先撞錯誤標的也不會越過它算答對。

追加驗證：四款遊戲 × 五種尺寸（667 × 375、390 × 844、844 × 390、768 × 1024、1024 × 768），共 20 組，沒有 JavaScript 例外、零尺寸畫布或頁面水平溢出；炸彈 HUD 快取隨旋轉更新。語法檢查通過，題庫 normalize／apply／hash 介面與語音解鎖函式維持原樣。
